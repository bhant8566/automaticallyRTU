2. 第一步：讀取 PDF 文字與座標
以下程式用來檢查 PdfPig 是否能成功取得文字與座標。


$ErrorActionPreference = 'Stop'

# PDF 與 DLL 路徑
$PdfPath = "C:\PDFReportSystem\InputPDF\Report_001.pdf"
$DllPath = "C:\PDFReportSystem\Lib\PdfPig.dll"
$Output  = "C:\PDFReportSystem\Output\RawWords.csv"

# 載入 PDF 函式庫
Add-Type -Path $DllPath

# 開啟 PDF
$pdf = [UglyToad.PdfPig.PdfDocument]::Open($PdfPath)

$results = New-Object 'System.Collections.Generic.List[object]'

try {
    foreach ($page in $pdf.GetPages()) {

        # GetWords() 取得文字與 bounding box
        foreach ($word in $page.GetWords()) {

            $box = $word.BoundingBox

            $results.Add([PSCustomObject]@{
                Page   = $page.Number
                Text   = $word.Text
                X      = $box.Left
                Y      = $box.Bottom
                Right  = $box.Right
                Top    = $box.Top
            })
        }
    }
}
finally {
    $pdf.Dispose()
}

# 匯出座標資訊
$results |
    Export-Csv -Path $Output `
               -NoTypeInformation `
               -Encoding UTF8

Write-Host "Extraction completed: $($results.Count) words"

這份程式有三個重點：

GetPages()：逐頁讀取 PDF，避免把整份文件的頁面物件全部保留在記憶體。

GetWords()：取得文字及其 Bounding Box，包含左、右、上、下座標。

Export-Csv：把擷取結果存成 CSV，供後續解析。

這是第一階段的基礎程式，尚未處理所有特殊 PDF 格式。實際能否執行，取決於安裝的 PdfPig 版本及相依 DLL 是否正確。

3. 第二步：依座標還原表格
假設你檢查 RawWords.csv 後，確認四個 column 的 X 座標範圍如下：

可以先用固定座標分區，實作第一版解析器。


$ErrorActionPreference = 'Stop'

$root = "C:\PDFReportSystem\Output"

$words = Import-Csv "$root\RawWords.csv"

# 同一 row 的 Y 座標容許誤差（PDF points）
$YTolerance = 3.0

# Column 的 X 邊界
$columns = @(
    @{ Name = "Date";      Min = 40;  Max = 140 }
    @{ Name = "Equipment"; Min = 140; Max = 260 }
    @{ Name = "Category";  Min = 260; Max = 400 }
    @{ Name = "Quantity";  Min = 400; Max = 500 }
)

$records = New-Object 'System.Collections.Generic.List[object]'

# 不同頁面必須分開處理
$pages = $words | Group-Object Page

foreach ($page in $pages) {

    # 從上到下、從左到右排列
    $sorted = $page.Group |
        Sort-Object `
            @{Expression = {[double]$_.Y}; Descending = $true},
            @{Expression = {[double]$_.X}; Ascending = $true}

    $rows = New-Object 'System.Collections.Generic.List[object]'
    $currentRow = New-Object 'System.Collections.Generic.List[object]'
    $referenceY = $null

    foreach ($word in $sorted) {
        $y = [double]$word.Y

        if ($null -ne $referenceY -and
            [math]::Abs($y - $referenceY) -gt $YTolerance) {

            $rows.Add($currentRow.ToArray())
            $currentRow = New-Object 'System.Collections.Generic.List[object]'
        }

        $currentRow.Add($word)
        $referenceY = $y
    }

    if ($currentRow.Count -gt 0) {
        $rows.Add($currentRow.ToArray())
    }

    foreach ($row in $rows) {

        $record = [ordered]@{
            Page = $page.Name
        }

        foreach ($column in $columns) {

            $matched = $row |
                Where-Object {
                    $x = [double]$_.X
                    $x -ge $column.Min -and
                    $x -lt $column.Max
                } |
                Sort-Object {[double]$_.X}

            $record[$column.Name] = (
                ($matched | ForEach-Object { $_.Text }) -join " "
            ).Trim()
        }

        $records.Add([PSCustomObject]$record)
    }
}

$records |
    Export-Csv "$root\Parsed.csv" `
        -NoTypeInformation -Encoding UTF8

Write-Host "Parsed rows: $($records.Count)"

這個版本適合固定欄位、單行資料、沒有跨欄或合併儲存格的 PDF 報表。

它目前仍有幾個限制：

Y 座標誤差是固定值，可能需要依字體大小調整。

多行文字可能被誤判成不同 row。

每頁標題與表頭也可能被當成資料。

文字橫跨 column 邊界時，可能被歸到錯誤欄位。

它是基礎解析器，還沒有完整的異常資料驗證。

因此不建議直接把這份初版程式用在正式報表，而是先拿一份 PDF 測試，再調整座標及 row 重建規則。

第一步：檢查 .NET Framework 版本
在 PowerShell 執行：

Get-ItemProperty `
    'HKLM:\SOFTWARE\Microsoft\NET Framework Setup\NDP\v4\Full' |
    Select-Object Release, Version

如果 Release 大於或等於 461308，通常代表已安裝 .NET Framework 4.7.1 或更新版本。

第二步：載入 PdfPig DLL
你的套件不是只有一個 DLL，而是拆分成多個組件，因此先測試載入整組 net471 DLL。


$ErrorActionPreference = "Stop"

$libPath = "$env:USERPROFILE\Desktop\PdfPigTest\Extracted\lib\net471"

# 檢查 DLL 是否存在
$dllFiles = Get-ChildItem $libPath -Filter "*.dll"

Write-Host "Found $($dllFiles.Count) DLL files"

# 先載入 Core 等底層組件，再載入主組件
$loadOrder = @(
    "UglyToad.PdfPig.Core.dll",
    "UglyToad.PdfPig.Tokens.dll",
    "UglyToad.PdfPig.Tokenization.dll",
    "UglyToad.PdfPig.Fonts.dll",
    "UglyToad.PdfPig.DocumentLayoutAnalysis.dll",
    "UglyToad.PdfPig.Package.dll",
    "UglyToad.PdfPig.dll"
)

foreach ($dll in $loadOrder) {
    $path = Join-Path $libPath $dll

    try {
        Add-Type -Path $path -ErrorAction Stop
        Write-Host "Loaded: $dll" -ForegroundColor Green
    }
    catch {
        Write-Host "Failed: $dll" -ForegroundColor Red
        Write-Host $_.Exception.ToString()
        break
    }
}

這裡的載入順序是初步測試用，並非已驗證的完整相依順序。如果某個 DLL 依賴其他 NuGet 套件，仍然可能出現載入失敗。
